# 模型平权 · Thinkpasser

**一家自营 AI 账号与订阅商城。技术应该解决问题，付费应该有所值得。**

用户选购具体的账号商品，确认套餐、独享/共享/代充方式、使用期限和价格，再完成购买与查看交付。商品由商店统一定价和经营。

> 本次交付只做前端。商城按自营店铺呈现，确认订单与收银台明确说明支付通道尚未开放、不会扣款。账号、密码、恢复代码随机生成，使用 `.test` 测试邮箱，不可真实登录。当前不包含真实支付、账号库存后台、邮件发送或跨设备登录功能。

## 本地运行

没有运行时依赖，无需安装 npm 包或构建。

```powershell
cd D:\selfProject\myself\thinkpasser
python -m http.server 4173 --bind 127.0.0.1
```

浏览器访问 **http://127.0.0.1:4173/**。也可以直接打开 `index.html` 浏览页面；使用本地 HTTP 服务更适合验证复制、下载和多标签同步。

安装了 Node.js 与 Python 时也可以使用 `npm run preview`。

## 页面与功能

| `#/order/<id>` | 收银台、交付账号、密码显示/隐藏、复制、下载、本地售后记录 |

## 完整体验一次购买

1. 在商城选择已有售价与库存的商品，进入详情页。待上架套餐可查看权益，不能下单。
2. 选择 1/3 个月期限和数量，加入购物车或立即购买。
3. 填写示例接收邮箱，选择支付宝或微信，确认购买须知。
4. 创建订单，进入收银台；页面说明支付通道暂未开放，不会实际扣款。
5. 点击“体验购买并查看交付”，每个购买单位生成一套体验交付信息。
6. 查看账号邮箱、密码、恢复代码、登录入口、具体到期日期及体验流水号。
7. 可以显示密码、复制单项/整套信息、下载文本或保存本地售后记录。刷新后仍展示同一套账号。

## 商品与品牌配置

在 `assets/store.js` 编辑 `BRANDS`、`PLAN_CATALOG` 和 `raw`。按 2026-10-23 核对的资料，当前收录 8 个品牌、43 个套餐条目（含保留的存量套餐），组合成 49 个商品。完整范围和官方来源见 [套餐核对记录](docs/catalog-audit-2026-10-23.md)。免费方案不作为付费商品售卖。

`PLAN_CATALOG` 保存套餐等级、权益说明、存量状态与官方链接；`raw` 保存店铺实际要配置的报价、库存和售卖方式。官方订阅价格与本店售价分别管理，不自动用外币官方价格推算店铺报价。

`raw` 每一行依次为：

```js
[商品ID, 品牌ID, 套餐名, 账号方式, 月价（整数分）, 库存, 交付方式, 描述, 标签]
```

账号/授权方式：`private` 独享、`shared` 共享、`topup` 代充、`team` 团队席位、`family` 家庭订阅。交付方式：`instant` 即时、`manual` 按单交付。

保留原有 16 个商品的价格、库存和 ID，避免影响已有购物车及订单。未配置报价的套餐自动生成 `price: null, stock: 0` 的待上架商品，显示“售价待确认”，不能加入购物车或创建零元订单，价格排序时放在最后，数值价格筛选时排除。上架时在 `raw` 增加相应配置，套餐名须匹配 `PLAN_CATALOG` 的 `tier` 或 `match`。

金额以人民币分保存，避免小数误差。当前 3 个月方案按月价的 2.85 倍计价。每笔订单保存成交时的商品与金额快照，之后修改商品配置不会改变历史订单金额。页面不再在商品卡片反复显示开发用的“示例”标记；前端配置不能替代真实运营的服务端验价和库存。

## 本地数据与异常恢复

- 浏览器存储键：`thinkpasser-store-v1`，包含购物车、收藏、演示订单与演示交付。
- 不沿用旧版预约数据存储，不会将预约误转为购买订单。
- 恢复时分别校验购物车、订单和交付字段；坏购物车条目不会清空有效订单。
- 异常原始内容备份到 `thinkpasser-store-v1-recovery-<时间戳>`；无法备份时停止覆盖保存。
- 支持存储事件同步与现代浏览器 Web Locks 串行写入，防止多个标签互相覆盖订单。
- 所有交付仅为随机演示数据。该存储方式不适合真实账号、真实支付记录或敏感信息。

## 未来接入真实交易

当前前台可独立展示与验收，真实运营仍需接入服务端的商品与库存、验价、订单身份验证、支付宝/微信商户、签名验证后的到账确认、真实凭证交付及售后处理。客户端模拟支付不能作为真实到账依据。根据用户要求，本次没有实现后端或发起任何真实支付，也没有修改线上部署。

静态托管需一并发布 `index.html` 与整个 `assets/` 目录。
