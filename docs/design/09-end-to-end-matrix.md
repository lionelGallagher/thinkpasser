# 端到端业务与异常验收矩阵

本表把四端动作落到统一业务、外部事实和失败处理。每行都要形成可自动复现的测试和真实集成证据；当前状态见[验证记录](verification.md)。技术和数据补充见[生产蓝图](08-production-implementation.md)。

## 入口和角色

| 主体 | 入口与允许动作 | 不授予的权限 |
| --- | --- | --- |
| 个人用户 | 网页／桌面：本人电脑、购买续费、AI、工单；交付自动使用，必要时开通团队 | 不必创建子账号；同一时间仅一台完整远控 |
| 主账号 | 网页／桌面：选电脑、付款、续费、加购、直接创建子账号、分配／收回、工单 | 团队管理不意味着能进入子账号桌面或导出其文件 |
| 子账号 | 网页／桌面：自己的独享电脑、账号设置、自己的导出及工单 | 不购买、不访问别人电脑、不看供应方秘密 |
| 电脑供方 | supplier：登记机器、接取机器维护／准备任务、回报证据、看自己的结算 | 资源所有权不自动获得客户桌面权限 |
| 纯卡供方 | supplier：登记卡引用、采购／供卡任务、回报、看自己的结算 | 不自动接取 AI 开通任务，不取得客户 AI 邮箱和认证资料 |
| 获核验开通方 | 卡／订阅侧能力：只接取获授权 provider／目标账号的任务 | 不能任意替换现成账号；不能以扣款代替可用验收 |
| 自营供货 | 同一 supplier 流程，按真实能力登记 | 不绕过验收，不生成对自己的虚假应付 |
| 管理人员 | 按细分权限管理资源、商品、任务、工单、资金对账 | 无默认客户桌面、无任意 shell、无明文凭据列表 |

## 购买、交付和供货

| 场景 | 前提与命令 | 同事务结果／幂等标识 | 外部完成条件 | 异常收口 |
| --- | --- | --- | --- | --- |
| 只买电脑 | main；可售 product → quote → order | quote 消费一次；unit 无 AI 项 | 电脑、镜像、真实连接、恢复／导出／清理能力验收 | 不等待未买 AI；资源失败按本 unit 异常决策 |
| 首单买一或两个 AI | quote 绑定每台账号来源及 provider | 每项稳定 entitlementId／orderItemId | 指定账号、订阅、登录、实际调用、完整上游覆盖 | 任一所购项未就绪不首次开放；不得串用另一订单同 provider 证据 |
| 多台分批 | 一单多个 unit | 各自 deliveredAt／lease／服务段 | 每套分别完整验收 | 一套失败不撤销已交付另一套；退款只分摊目标项目 |
| 支付回调重放 | 已验签事件 | providerEvent、receipt 唯一 | query／真实渠道确认 | 相同 event 不重入账；相同交易不同通知仍同一事实 |
| 两笔不同成功款 | 同一 order 多个 attempt | 仅一 receipt 被接受履约 | 多收款原路退／待核查 | 不重复备机或增租期，不删除另一笔成功事实 |
| 取消后迟到付款 | order 已取消 | receipt exception，退款预留／outbox | 原渠道退款结果 | 不重开订单，不抢已释放库存 |
| 纯卡商提前供卡 | 可审核的脱敏资源／报价 | supplyPurchase、instrumentRef、资金预留 | 资源／授权验收；采购付款单独核实 | 无客户单也可采购；卡商 verified 不激活 AI |
| 分工开通 | 卡资源＋获核验执行方 | 精确 task/attempt/account/entitlement 绑定 | 上游操作事实＋平台可用探针 | 卡商不获得目标账号；unknown 原操作查询，禁止重复付款 |
| 一体或自营供货 | 供卡、开通分别审核 | 同一供方可多能力；成本单独记 | 与合作供方同验收 | 自营失败同售后；不造自营应付 |
| 取消后迟到开通 | 旧 task cancelled／旧履约代际 | 追加 upstreamResult 和成本事实 | 对账、隔离／授权回收 | 不改终态、不交付原客户、不复制令牌卖给别人 |
| 上游期限不足 | 任务可能已较早验收 | 最终 deliver 重核覆盖 | upstreamUntil 覆盖最终承诺段 | unit exception；不得扣起租一天来掩盖缺口 |
| 商品改价 | 管理端发布新版本 | 新 quote 新 snapshot | 无 | 旧订单和原支付金额不变 |
| 等待、退该套、改纯电脑 | reason＋unit resolution quote | 冻结版本、逐项金额、条款 hash、确认 | 停止新上游动作、对账在途成本后执行 | 正常主动取消依已确认真实成本；平台失败不扣上游不可退成本；已交付正常买定离手 |

## 续费、加购和账号使用

| 场景 | 前提与命令 | 核心状态／时间 | 失败与恢复 |
| --- | --- | --- | --- |
| 电脑续费 | main；lease 未开始清理 | 原截止＋周期；新 computer segment；唯一 leaseEvent | 付款成功但版本／清理条件失败保留资金事实，异常退款／重新确认，不谎报旧环境恢复 |
| 提前续费不选 AI | 电脑有效、有旧 AI | 电脑增加新段；旧 AI 保持原截止 | 不提前撤销旧 AI，不免费延 AI |
| 连续两次含同种 AI 续费 | 各自新 entitlement／相邻段 | 验收按精确 ID，旧有效段继续 | 第一笔任务通过不能激活第二笔；新段失败只处理该项目 |
| 已有电脑加购 | 电脑有效；无同 provider 重叠项 | 标准全价；付款冻结原电脑截止；承诺段不因补时改写 | 验收仍不可用保持 preparing；原截止已过进入异常，不激活过期项 |
| 同时等待两个 AI | 两任务起止重叠 | 电脑等待区间取并集，只补新增量 | 不给每个任务重复补一遍；不延 AI 原截止 |
| 自动续费 | main 明确 opt-in 且渠道具备授权 | 唯一周期键；当前组合快照；到期任务幂等 | 扣款 unknown 先查；失败提示人工续费，不无限扣款 |
| 直接建子账号 | main 与 sub 同 tenant | firstLogin、临时密码只经安全通道 | 邮箱冲突／密码不合规失败不创建半成品；无邀请流程 |
| 分配电脑 | 电脑已交付，账号无有效／预留分配 | 唯一 assignment；main 可分给自己一台 | 双并发分配只有一成功；团队管理不取得桌面资格 |
| 保留文件换人 | 同租户确认交接 | 旧授权撤销；pendingAssignment；新 OS 身份／私密登录处理 | 收到凭据／环境验收才 active；失败保持不可进入，不先标在线 |
| 清空换人 | 客户确认破坏性动作 | reset operation 与版本栅栏 | 结果 unknown 不能重派另一 wipe；验收后才给新人 |
| 多账号切换 | 多个已独立登录会话 | activeAccount 切换；旧本地输入与续租停止 | 权利不合并；切回仍重新核验有效期和分配 |
| 禁用或改密 | 主体有权限 | authVersion／epoch 递增；刷新会话失效 | 旧 grant、旧刷新、旧连接均不能继续；设备通知失败靠本地截止兜底 |

## 远控和生命周期

| 场景 | 后端／设备机制 | 前端可显示的完成状态 | 必须故障注入验证 |
| --- | --- | --- | --- |
| 正常连接 | ConnectionAttempt → challenge/proof → RustDesk auth → SessionReady → active | 首帧及受控通道就绪后已连接 | 无适配器返回 ADAPTER_NOT_CONFIGURED，不使用本地画面冒充 |
| 旧连接接管 | 绑定旧 sid 的确认；closing 占位；可信 CloseAck 后新 pending | 等待旧连接关闭 → 建立中 → 已连接 | 丢 CloseAck 不允许两 active；旧确认不能关闭新 session |
| 网络重连 | 同 key、sid、新 connectionGeneration，旧传输关闭 | 重新连接中 | 旧连接迟到数据／旧 challenge／旧 boot 拒绝 |
| AI 到期 | 只更新 AI 权益 | AI 到期提示，电脑仍可连接 | 电脑授权完全不依赖是否买 AI |
| 电脑到期 | revoke＋epoch；设备单调时钟截止；外部隔离 | 已到期，仅导出／续费 | 平台断网、设备时钟回拨、旧客户端／直连旁路均不得越界 |
| 断开客户端 | 关闭媒体和输入，保留 OS 开发任务 | 已断开 | 不注销远端 OS 或杀 Claude／Codex 进程 |
| Mac 长期连接故障 | 心跳／服务／寻址／桌面探针分层；先查再受控恢复 | 恢复中；探针后已恢复 | 长时运行、睡眠唤醒、端口／实例泄漏；无法复现不能声称已修复 |
| 重启服务／OS | commandId 持久 claimed；新实例／新 boot 验证 | 已受理≠已恢复 | 超时未知原编号核查，禁止盲目升为重装 |
| 三天保留导出 | 原使用者授权、独立只读面、manifest／分块、截止中断 | 导出准备／可下载／已过期 | 路径穿越、符号链接／reparse 竞态、长流跨截止必须拒绝或终止 |
| 保留期内续费 | 同 lease 锁，沿旧截止恢复 | 原环境恢复后可连接 | 旧账号若已有另一台，需先解决分配冲突，不能双占用 |
| 保留期末清理 | 先关导出；expectedLeaseVersion；独立重置与探针 | 清理中 → 验收后可售 | 与续费／补时竞争、回执丢失、残留文件和登录；unknown 隔离 |
| 主动换购 | 新 full-price order，旧先自行导出并确认清空 | 新套准备／交付，旧结束 | 旧电脑与旧 AI 不退不抵；不误走故障续约 |
| 故障换机 | 同 lease，新 allocation；重建登录，旧入口撤销 | 替代机可用 | 不双机 active、不重置原服务时段、不收主动换购价 |

## 工单、退款和结算

| 场景 | 规则与账务结果 | 不能省略的条件 |
| --- | --- | --- |
| 无工单监控故障 | 可修复，不自动补时退款 | 监控事件不冒充客户申请 |
| 电脑普通故障 | 核实后按并集补电脑；已购且同受影响 AI 按原段现金赔付 | 普通电脑补时申请遵守到期前至少三天；纯电脑无 AI 退款 |
| AI 窗内修复 | 有限修复窗口，窗内恢复不退 | 修复结果需实际可用证据，不能把接单当恢复 |
| AI 超窗未恢复 | 核实起点到原承诺末尾退款，含修复等待；终止该项 | 电脑、另一 AI 继续；退款分母和原价不可改 |
| 严重电脑故障结束 | 逐电脑／AI 服务段算未提供部分；结束平台 AI | 回各原支付，不把上游不退作为拒退客户依据 |
| 重叠工单 | 故障区间并集；扣已成功及预留退款 | 同一时间不重复补或重复退；电脑补时和 AI 退款可并存 |
| 退款响应丢失 | reserved → submitted → unknown，保留占用 | 原退款号查询；确认失败才释放，不换号重复转款 |
| 供方结算 | 验收成本→核定义务→预付抵扣→结算→凭证对账 | 资源已验收不意味着已付款；客户退款不等于自动扣供方钱 |
| 自营成本 | 内部成本、上游付款、分摊 | 无对自身应付；与对外合作账分开 |
| 财务更正 | 追加调整／冲正及审批证据 | 不删除资金事实，不靠修改历史订单金额平账 |

## 持久化和集成测试清单

测试实现必须使用独立 MySQL 8.4，不触碰用户本地业务库。每个竞争场景用两个独立连接和屏障控制交错；验证行、唯一键、outbox 和外部调用次数，而不只检查 HTTP 状态。

1. 同一个报价重复提交、同账号双分配、同机器双 allocation、两次接管并发、接管与禁用并发。
2. 支付通知重复／乱序、两笔真实成功款、成功后 worker 崩溃、取消后成功、退款 unknown 后实际成功。
3. 纯卡验收不能激活 AI；能力不符拒绝派单；精确账号／权益／attempt 串错；取消后迟到开通只记事实。
4. 两笔同 provider 续费交叉回报、交付前上游覆盖过期、加购截止过期、等待和故障区间重叠。
5. 续费／补时与到期／清理交错；旧租约版本 wipe 被拒；导出流到时中断后才清理；重置 unknown 不回库。
6. 多售价多支付服务段部分故障／终止；累计退款不超过原项目和 receipt；重叠工单并发预留。
7. 服务、数据库、信令、设备进程中断后恢复；旧 worker／旧 boot／旧 grant 不能覆盖新状态。

设备真机、支付渠道、供应接口和浏览器兼容性不由 schema 校验替代。尚未接入的能力必须保持待验证状态，不能用“生产级设计”给未实现功能盖章。
