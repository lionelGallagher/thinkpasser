## 2. 个人与团队是空间模式

`tenant.kind`仍区分customer／supplier／platform；customer另有`workspace_kind=personal/team`。用户全局登录身份和商业角色不混为一谈：个人拥有者在内部可复用main权限，界面显示“个人账号”；只有团队才显示主账号／子账号。supplier／admin身份不携带客户workspaceKind，不因客户模式字段获得客户权限；sub只能属于team。不是给个人创建一套新的AI商城或卡商城。

注册默认personal，可显式创建team。个人空间只有一个使用者，不开放创建子账号；个人每次买一台，可有旧机保留导出及新机准备／等待切换，但同时最多一台完整远控。团队主账号可购买多台，按原规则分配给自己或子账号。个人和团队共享电脑规格、可选AI、付款渠道、起租、到期、三天导出和售后算法。

`GET /me/workspace`返回空间模式及能力；`POST /me/workspace/upgrade-to-team`由拥有者执行，比较空间版本。升级沿用同一tenant、账号、订单、电脑、租约、账号登录和AI权益，既不重启租期也不产生迁移退款。若有控制位尚未转移收口的个人换机／破坏性交接操作，先完成或核查该操作，不在中途切换空间规则。首期不提供将有子账号的团队直接降级为个人的入口。

## 3. 个人购买与换机

个人首单：下单付款 → 准备电脑和本次所购AI → 整套验收 → T12同时锁拥有者控制位；无其他有效控制位时自动分配本人，不要求用户去团队页点分配。主账号是原order.payer的业务身份，不能误用负责交付的管理员身份。交付即起租，断开客户端仍保留远端任务运行。

已有有效电脑时再买：按全价新订单准备，原服务照常；新机准备好交付后沿交付时间计时，并明确显示“待切换”。不自动踢掉旧电脑，更不自动复制文件或沿用旧AI余额。客户先自行导出，然后确认切换及旧数据清除、不退不抵。

`POST /machines/{id}/activate`只允许personal拥有者，绑定目标版本、原机器ID／版本和确认token。T05先关闭旧会话全部通道并获得可信回执，再释放旧控制位、终止旧套平台AI、将旧机置清理／隔离，向本人开放新机；旧机清理不必阻塞新机使用，但未知结果不能回可售库存。新订单AI仍独立购买。重复确认只返回原activation，旧环境已开始清理后不能再承诺恢复。

原机器已到期时，没有活跃控制位，新机可正常开放；原三天导出归属继续保留，不等于同时控制两台。清理期限和只读导出规则不变。接口查询`personal-activations/{id}`，等待关闭／开放／异常都应有明确状态。

## 4. 账户、导出和报价一致性

生产数据库采用统一account_computer_slots保证有效控制位；assignedTo历史不可当作永久占位。到期时释放活跃资格，并保存export_ownership。保留期续费时重新竞争控制位：同账号已使用另一台，不得偷偷同时恢复旧机完整桌面。

导出检查有效平台身份、原exportOwner、lease／allocation、exportJob和三天截止；主账号收回不自动拥有子账号文件。新使用者交接完成后才建立新的实际使用身份，旧私人登录按原设计独立清理。

报价和订单保存电脑截止、leaseVersion、逐项金额及条款hash。付款应用前若租期／目标／价格发生影响条款的变化，不能悄悄改AI承诺；需要新报价与明确确认。真实渠道已成功但报价失效的资金事实必须保存，进入异常对账／原路退款，不准简单返回“没付款”或重复扣费。演示拒绝模拟付款，是为了避免生成假交付，不是生产资金回调处理方式。

续订使用原aiAccountId，来源为existing；不能通过email替换现成账号。renewal未提交目标时，服务端从该lease原provider账号推导；提交existing时验证tenant、lease和provider。只有没有该provider账号的新开通项才使用platform/customer来源；已有provider的续订试图改用新邮箱须返回TARGET_ACCOUNT_MISMATCH。两笔相邻续订各有entitlementId，账号身份相同不等于共用同一权益记录。

## 5. 严重故障方案确认

管理员核实事实并`POST /admin/tickets/{id}/offers`；系统从原服务段计算方案，冻结每个原orderItem／receipt应退金额、币种、条款hash、ticketVersion和截止。`GET /tickets/{id}/offer`及`POST /tickets/{id}/offer/accept`仅向原付款主账号开放。客户确认fault_replace或terminate_unit_refund，管理员decision引用acceptedOfferId，不得替客户暗中选择。

普通电脑故障仍是符合资格的电脑补时＋已购受影响AI现金赔付，不退普通电脑故障现金。AI单项超修复窗按原规则结束该项并退款；现金计算要求核实区间和证据。严重结束该套才按允许场景处理电脑未提供费用。时间范围、原项目金额、已退及预留由服务器复核，不能信任前端计算出的退款数值。

## 6. 设备事件的可执行投递路径

首期设备控制面可用mTLS长轮询，不依赖未定义的WebSocket实现。`POST /agent/poll`携afterRemoteCursor，已签AgentPollResult含command、remoteEvents、nextRemoteCursor；command仍是受限设备命令，remoteEvents是平台签名SessionRevoke、SessionActivated、RenewGrant等消息。空批返回空数组，不能用没有字段的另一种响应。

设备验证消息、按messageId去重，使用`POST /agent/session-events`回报签名SessionReady、SessionActivationAck、CloseAck、RenewAck。T13先保存认证事实，T07按统一锁序重核并应用，202只表示收到。重发同消息不重复消费challenge或重复开放；旧boot／epoch／generation不能改变当前会话。poll cursor只证明投递进度，不代表物理关闭／激活成功；后者依对应业务ack。

控制面签名消息外层限64KiB；聚合解码payload工程上限44KiB，每批最多10项且还需按总字节截断，不能只看条数。长轮询可以等待，出现事件立即唤醒；客户端重试带原cursor，平台保留未确认业务动作并按原消息号重投。

浏览器媒体的SDP／ICE交换和RustDesk原生守卫仍需原生适配器验证，不能把上述控制面投递当成浏览器已可远控。完整媒体协商、身份绑定、首帧和到期关闭证据属于下面的上线阻断项。
